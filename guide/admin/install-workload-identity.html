Install workload identity

SPIRE issues the JWT-SVIDs that sandbox supervisors present to the identity provider (IdP). On OpenShift, the Zero Trust Workload Identity Manager operator deploys and configures SPIRE. This page installs the operator, creates its five operand resources, and verifies the result. How it works shows where each component takes part in a token grant.

The commands and manifests on this page ran against operator version 1.1.2 from the stable-v1 channel.

Before you begin

  • You have access to the cluster with cluster-admin privileges.

  • The SPIRE server can claim a persistent volume of at least 1Gi.

  • Your cluster can install operators from the redhat-operators catalog source in openshift-marketplace.

Choose the trust domain and the JWT issuer

The trust domain is the authority part of every SPIFFE ID, spiffe://<trust-domain>/<path>, and the cluster name identifies this cluster inside the trust domain. Both are fields of the ZeroTrustWorkloadIdentityManager resource, and neither can change after you create it.

The operator derives Route hosts from these values. The Route of the OIDC discovery provider uses the host part of jwtIssuer, and a federation Route, when configured, uses federation.<trust-domain>. Red Hat recommends the cluster’s apps domain as the trust domain. This page uses the apps domain as the trust domain and https://oidc-discovery.<apps-domain>; as the JWT issuer. The default ingress controller serves *.<apps-domain>, which includes the issuer host.

  1. Read the apps domain of your cluster.

    Check: the command prints one DNS name, which is <apps-domain> in the rest of this page.

    oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}'

  2. Choose <cluster-name>. It must be a DNS subdomain name of at most 63 characters: lowercase letters, digits, hyphens, and dots, starting and ending with a letter or digit.

Install the operator

The operator runs in the zero-trust-workload-identity-manager namespace. The OperatorGroup and the Subscription follow the Red Hat installation procedure for the command line.

  1. Create the Namespace, the OperatorGroup, and the Subscription.

    oc apply -f - <<'EOF'
apiVersion: v1
kind: Namespace
metadata:
  name: zero-trust-workload-identity-manager
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: openshift-zero-trust-workload-identity-manager
  namespace: zero-trust-workload-identity-manager
spec:
  upgradeStrategy: Default
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: openshift-zero-trust-workload-identity-manager
  namespace: zero-trust-workload-identity-manager
spec:
  channel: stable-v1
  name: openshift-zero-trust-workload-identity-manager
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF

  2. Wait for the operator to install. Repeat the command until the CSV shows Succeeded.

    Check: the CSV whose name starts with zero-trust-workload-identity-manager.v reaches the phase Succeeded.

    oc get csv -n zero-trust-workload-identity-manager

Create the operands

The operator manages SPIRE through five cluster-scoped resources. Each one is a singleton, and its name must be cluster. Red Hat documents this creation order: ZeroTrustWorkloadIdentityManager, SpireServer, SpireAgent, SpiffeCSIDriver, SpireOIDCDiscoveryProvider.

  1. Create the ZeroTrustWorkloadIdentityManager resource with your trust domain and cluster name.

    oc apply -f - <<'EOF'
apiVersion: operator.openshift.io/v1alpha1
kind: ZeroTrustWorkloadIdentityManager
metadata:
  name: cluster
spec:
  trustDomain: <apps-domain>
  clusterName: <cluster-name>
  bundleConfigMap: spire-bundle
EOF

    bundleConfigMap names the ConfigMap in which the operator keeps the trust bundle. spire-bundle is its default, and the field is immutable.

  2. Create the SpireServer resource.

    oc apply -f - <<'EOF'
apiVersion: operator.openshift.io/v1alpha1
kind: SpireServer
metadata:
  name: cluster
spec:
  jwtIssuer: https://oidc-discovery.<apps-domain>
  caKeyType: rsa-2048
  defaultJWTValidity: 5m
  caSubject:
    commonName: SPIRE Server CA
    organization: <cluster-name>
    country: US
  persistence:
    size: 1Gi
    accessMode: ReadWriteOnce
  datastore:
    databaseType: sqlite3
    connectionString: /run/spire/data/datastore.sqlite3
EOF

    jwtIssuer must match the issuer of the OIDC discovery provider in a later step. caKeyType sets the key type of the server CA for both X.509 and JWT; rsa-2048 is the default. defaultJWTValidity is the lifetime of a JWT-SVID whose registration entry sets none; 5m is also the default. caSubject.country takes a two-letter ISO 3166-1 code. persistence cannot change after creation. Without persistence.storageClass, the operator sets no storage class on the SPIRE server’s volume claim. The datastore values are the defaults: an SQLite file in the server’s data volume at /run/spire/data.

    Leave federation unset. The SpireServer resource rejects an update that removes federation once it is set. Keycloak accepts an OpenID Connect JWKS endpoint as its SPIFFE bundle endpoint, and this guide points it at the /keys endpoint of the OIDC discovery provider, so the guide needs no federation.

  3. Create the SpireAgent resource with explicit attestors.

    oc apply -f - <<'EOF'
apiVersion: operator.openshift.io/v1alpha1
kind: SpireAgent
metadata:
  name: cluster
spec:
  nodeAttestor:
    k8sPSATEnabled: "true"
  workloadAttestors:
    k8sEnabled: "true"
    workloadAttestorsVerification:
      type: auto
EOF

    The operator adds a node attestor plugin only when nodeAttestor is present with k8sPSATEnabled: "true", and a workload attestor plugin only when workloadAttestors is present with k8sEnabled: "true". Without these fields, the operator configures no attestor plugins. k8sPSATEnabled selects the k8s_psat node attestor, configured with the cluster name. k8sEnabled selects the Kubernetes workload attestor, which finds the calling Pod through the kubelet. workloadAttestorsVerification.type: auto makes the agent verify the kubelet certificate against /etc/kubernetes/kubelet-ca.crt. Without workloadAttestorsVerification, the operator configures the agent to skip kubelet certificate verification.

  4. Create the SpiffeCSIDriver resource.

    oc apply -f - <<'EOF'
apiVersion: operator.openshift.io/v1alpha1
kind: SpiffeCSIDriver
metadata:
  name: cluster
spec: {}
EOF

    The defaults name the CSI driver csi.spiffe.io and share the agent socket directory /run/spire/agent-sockets with the SPIRE agent. The driver mounts that directory into Pods that request a csi.spiffe.io volume. The Workload API socket file in it is spire-agent.sock.

  5. Create the SpireOIDCDiscoveryProvider resource with the same issuer as the SpireServer.

    oc apply -f - <<'EOF'
apiVersion: operator.openshift.io/v1alpha1
kind: SpireOIDCDiscoveryProvider
metadata:
  name: cluster
spec:
  jwtIssuer: https://oidc-discovery.<apps-domain>
EOF

    With the default managedRoute: "true", the operator creates the Route spire-oidc-discovery-provider with the issuer host, re-encrypt TLS termination, and a redirect from HTTP.

The operator sets the tolerations of the SPIRE agent and SPIFFE CSI driver DaemonSets from spec.tolerations of their resources. The scheduler does not place their Pods on a node with a NoSchedule taint they do not tolerate. The CSI driver registers csi.spiffe.io with the kubelet of each node it runs on. When the SPIFFE socket is configured, OpenShell supervisor Pods mount a csi.spiffe.io volume, which needs the driver registered with the kubelet of their node. When sandboxes run on tainted nodes, add a matching toleration to spec.tolerations of both SpireAgent and SpiffeCSIDriver:

spec:
  tolerations:
  - key: <taint-key>
    operator: Exists
    effect: NoSchedule

The operator sets the ZeroTrustWorkloadIdentityManager resource as owner of the other four resources. Deleting the ZeroTrustWorkloadIdentityManager resource deletes the operands and their resources.

Verify the installation

  1. Check the overall status.

    Check: the conditions Ready and OperandsAvailable are True.

    oc get zerotrustworkloadidentitymanager cluster -o jsonpath='{range .status.conditions[*]}{.type}={.status}{" "}{end}'

  2. Check the DaemonSets. Compare DESIRED with the number of nodes where sandboxes run.

    Check: for spire-agent and spire-spiffe-csi-driver, the READY count equals the DESIRED count.

    oc get daemonset spire-agent spire-spiffe-csi-driver -n zero-trust-workload-identity-manager

  3. Check the CSI driver label.

    Check: the operator labels the CSIDriver csi.spiffe.io with the restricted ephemeral volume profile.

    oc get csidriver csi.spiffe.io --show-labels

  4. Check the OIDC discovery document.

    Check: the discovery document at the issuer lists a jwks_uri that ends in /keys.

    curl -sS "https://oidc-discovery.<apps-domain>/.well-known/openid-configuration"
