Configuration

This page lists the configuration that this guide sets or relies on, for Administrators and Users. Each table names the guide page that uses its fields. The column "This guide" shows the value that the guide pages use, with the placeholders of those pages. In the Default column, Required means that the field has no default and must be set, and a dash means that the source states no default.

OpenShell Helm values

Configure OpenShell sets the socket path in the values of the OpenShell Helm release.

Key This guide Default Description

gatewayConfig.openshell.drivers.kubernetes.provider_spiffe_workload_api_socket_path

/spiffe-workload-api/spire-agent.sock

Not set

Path of the SPIFFE Workload API socket inside the gateway Pod and the supervisor Pods. The chart renders it into gateway.toml as provider_spiffe_workload_api_socket_path in the [openshell.drivers.kubernetes] table. With a path set, the chart mounts a read-only csi.spiffe.io volume at the parent directory of the path into the gateway Pod, and the driver mounts one into the supervisor container of each supervisor Pod. An empty or omitted path disables the socket. The driver rejects a relative path, surrounding whitespace, and a socket directly under /.

server.providerTokenGrants.spiffe.enabled

Not set

false

Deprecated alias. With true, the chart uses workloadApiSocketPath as the socket path, but only when gatewayConfig does not set provider_spiffe_workload_api_socket_path.

server.providerTokenGrants.spiffe.workloadApiSocketPath

Not set

/spiffe-workload-api/spire-agent.sock

Deprecated alias. The socket path that enabled: true applies.

In gatewayConfig, each top-level key names a TOML table, so openshell.drivers.kubernetes is a single YAML key that holds provider_spiffe_workload_api_socket_path.

ClusterSPIFFEID

Register sandbox identities creates the ClusterSPIFFEID openshell-sandbox-supervisors with these fields. The ClusterSPIFFEID reference describes the fields that this guide leaves unset.

Field This guide Required Description

spec.className

zero-trust-workload-identity-manager-spire

No

Class name of the SPIRE Controller Manager. Zero Trust Workload Identity Manager configures the controller manager with this class name and without watching resources that have no class name, so the controller manager ignores a ClusterSPIFFEID that lacks it.

spec.spiffeIDTemplate

spiffe://{{ .TrustDomain }}/openshell/sandbox/{{ index .PodMeta.Annotations "openshell.ai/sandbox-id" }}

Yes

Template that renders the SPIFFE ID. {{ .TrustDomain }} is the trust domain that the controller manager operates for, and {{ .PodMeta }} is the Pod metadata. The driver writes the openshell.ai/sandbox-id annotation on the supervisor Pod.

spec.namespaceSelector

kubernetes.io/metadata.name: <namespace> in matchLabels

No

Label selector for the namespaces. Kubernetes sets the kubernetes.io/metadata.name label on every namespace.

spec.podSelector

openshell.ai/managed-by: openshell, openshell.ai/component: supervisor, and openshell.ai/boundary-role: supervisor in matchLabels

No

Label selector for the Pods. The driver sets these labels on the supervisor Pod.

spec.workloadSelectorTemplates

k8s:container-name:supervisor and k8s:pod-name:os-supervisor-{{ index .PodMeta.Annotations "openshell.ai/sandbox-id" }}

No

Templates that render additional selectors for each entry. The controller manager always adds k8s:pod-uid:<pod-uid> as well. The SPIRE agent serves an entry only when all of its selectors are among the selectors attested for the caller.

spec.fallback

Not set

No

Applies the SPIFFE ID only when no non-fallback ClusterSPIFFEID matches the Pod. Zero Trust Workload Identity Manager creates the fallback ClusterSPIFFEID zero-trust-workload-identity-manager-spire-default with the SPIFFE ID spiffe://<trust-domain>/ns/<namespace>/sa/<service-account>. It applies in every namespace except the operator namespace and the namespaces that the controller manager ignores: kube-system, kube-public, local-path-storage, and openshift-*.

With this registration, SPIRE attests the Pod UID, the container name, and the Pod name of the caller. The <sandbox-id> segment of the SPIFFE ID comes from the Pod annotation that the Pod creator writes, and SPIRE does not attest it. Trust model explains what attestation proves and what it leaves open.

Keycloak

Install Keycloak sets the feature in the Keycloak resource. Configure Keycloak sets the identity provider in the KeycloakRealmImport and describes the client for each sandbox.

Keycloak resource

Field This guide Description

spec.features.enabled

spiffe

Keycloak features to enable. spiffe enables the SPIFFE identity provider, a preview feature that is disabled by default.

SPIFFE identity provider

The SPIFFE identity provider is an entry of spec.realm.identityProviders in the KeycloakRealmImport.

Key This guide Description

alias

spiffe

Name that each client references in its jwt.credential.issuer attribute.

providerId

spiffe

Selects the SPIFFE identity provider.

enabled

true

Enables the identity provider.

config.trustDomain

spiffe://<trust-domain>

Trust domain with the spiffe:// prefix and no trailing slash. The identity provider rejects a sub that does not start with this value followed by /. It also rejects a trust domain that is not spiffe:// followed only by lowercase letters, digits, dots, hyphens, and underscores, so a trailing slash fails validation.

config.bundleEndpoint

https://oidc-discovery.<apps-domain>/keys

HTTPS URL of a SPIFFE bundle endpoint or of an OpenID Connect JWKS endpoint. The identity provider fetches the signing keys from it with HTTP GET. The SPIRE OIDC discovery provider serves its JWKS at /keys.

Other profile fields

Field This guide Description

id

<profile-id>

Profile ID in lowercase kebab-case, with a-z, 0-9, and -. It is the value of --type in openshell provider create.

category

other

Informational only.

credentials[].required

false

Makes the credential optional. A provider can be created without stored credentials when every credential is optional or resolved at runtime.

credentials[].auth_style

bearer

With header_name: Authorization, injects the token as Authorization: Bearer <token>. Omitting both auth_style and header_name selects the Authorization header. An explicit bearer or header style requires header_name, and the profile fails validation without it.

credentials[].header_name

Authorization

Header that receives the token. The injection replaces every instance of the header that the agent sent.

endpoints[].host, endpoints[].port

<api-host>, <api-port>

Destination of the requests. The supervisor injects the token only into requests to matching profile endpoints.

endpoints[].protocol

rest

Enables request inspection.

endpoints[].access

read-only

Preset of allowed methods. read-only allows GET, HEAD, and OPTIONS, read-write adds POST, PUT, and PATCH, and full allows all methods and paths.

endpoints[].enforcement

enforce

Blocks requests that break the endpoint rules.

endpoints[].tls

Not set

Accepts only an empty value or skip. When omitted, OpenShell terminates TLS automatically. A profile with a token grant rejects skip, because skip bypasses the header injection.

binaries

/usr/bin/curl and <client-binary>

Executables allowed to reach the endpoints, listed by their real paths, not symlinks. For a script, the executable is its interpreter. A listed binary also covers the processes it starts.
